# Спека: новая схема каталога киосков

> Черновик для согласования. Ветка `feature/kiosk-catalog-redesign`.
> Дата: 2026-07-08. Автор: Claude (по задаче Владлена).
> Визуальная версия: artifact «Каталог киосков — новая схема».

Цель — убрать три класса ошибок менеджеров:
1. **Дрейф цен** — планшетный Kiosk берёт железо из хардкода, а не из таблицы.
2. **Догадки кода** — категория/крепление/фискалка угадываются по подстрокам в названии.
3. **Каша при сборке киоска** — 28 карточек-вариантов, сканер в трёх разных логиках, обязательные и дополнительные опции неразличимы.

---

## 1. Принцип: один источник, две проекции

Ты правишь **номенклатуру** (читаемый прайс). Структурную модель для генератора код
собирает сам при загрузке. Синхронизировать руками ничего не надо.

```
  Номенклатура (правишь)  ─┐
                           ├─►  [код: сборка на лету]  ─►  Каталог генератора (форма + КП)
  Правила семейств (редко) ─┘
```

Ни один факт не вводится дважды: **цены** живут в «Номенклатуре», **правила семейства**
(имя для клиента, форм-фактор, фискальный паттерн) — в «Правилах семейств». Это не копия,
а два ортогональных среза.

---

## 2. Вкладка «Номенклатура» — одна строка на SKU/компонент

| Колонка | Обязательна | Значения | Комментарий |
|---|---|---|---|
| `Семейство` | да | напр. `МС 21 N` | Ключ связи с «Правилами». Код нормализует регистр/пробелы. |
| `Тип` | да | `модель` · `крепление` · `опция` · `фискал` | Явно. Больше не угадывается по имени. |
| `Наименование` | да | текст | Внутреннее имя (с брендом) — видит только менеджер. |
| `Процессор` | для моделей | `N100` `i3` `i5` `N97` `N95` `J6412` | Ось комплектации. Пусто у не-моделей. |
| `Сканер` | для моделей | `в корпусе` · `нет` | Ось комплектации, если сканер — заводская сборка (SKU-вариант). Иначе сканер — отдельная строка `опция`. |
| `Исполнение` | опц. | `Белый` `Чёрный` · … | Доп. ось (цвет/тир корпуса), где есть. |
| `Обязательность` | для крепл./опций | `в комплекте` · `обязательная` · `опция` | Как позиция попадает в смету. Пусто у моделей. |
| `Взаимоисключение` | опц. | ключ группы, напр. `принтер` | Позиции с одним ключом — radio (нельзя выбрать две, напр. принтер 58 vs 80). |
| `Себестоимость` | да | число | Как сейчас. |
| `Цена` | да | число | Как сейчас. `0` = включено в комплект (для строк «в комплекте»). |
| `НДС`, `Поставщик`, `Фото` | опц. | — | Как сейчас. |

**Клиентское имя (`Имя для КП`) для моделей НЕ пишется руками** — оно собирается из «Правил
семейств» (см. §4). Для опций/фискалки клиентское имя — из короткого словаря обезличивания
(`Сканер ШК`, `Принтер чеков`, `Фискальный регистратор`).

### Как оси комплектации превращаются в селектор
Форма группирует строки `Тип=модель` по `Семейству`, берёт различные значения `Процессор` /
`Сканер` / `Исполнение` и рисует переключатель на каждую ось, где >1 варианта. Выбранная
комбинация резолвится ровно в одну строку-модель (её цена). Так 4 карточки МС 21 N
(N100/i3 × со/без сканера) становятся одной карточкой с двумя переключателями.

## 3. Вкладка «Правила семейств» — ~12 строк

| Колонка | Значения | Комментарий |
|---|---|---|
| `Семейство` | напр. `МС 21 N` | Совпадает с «Номенклатурой». |
| `Имя для КП` | «Касса самообслуживания 21.5″» | Шаблон клиентского имени. Может нести `{форм-фактор}`. |
| `Диагональ` | `21.5″` | Для клиентского имени и подписи карточки. |
| `Форм-фактор` | `настольный` · `настенный` · `напольный` | Дефолт крепления + суффикс имени. |
| `Фиск. паттерн` | `внешний` · `внутренний` · `нет` | Определяет фискальный пакет (см. §5). |
| `Встроенный принтер` | `80мм` · `58мм` · `—` | Для внутреннего паттерна, если принтер НЕ в комплекте модели. |
| `Процессор по умолч.` | `N97` | Что выбрано в селекторе по умолчанию — самый ходовой/дешёвый. |

## 4. Деривация клиентского имени

```
Имя для КП (модель) = <Правила.Имя для КП>            // напр. «Киоск самообслуживания 24″ (напольный)»
Имя для КП (опция)  = Наименование (уже безбрендовое)
Имя для КП (фискал) = Наименование как есть — РЕАЛЬНОЕ имя (см. ниже)
```

Заполнил семейство один раз — все его МОДЕЛИ обезличены одинаково, без опечаток и
брендов: никаких «POScenter», «Sam4s», «SuperKiosk», «МС», латиницы в КП клиента.

**Исключение — фискальное оборудование показывается РЕАЛЬНЫМ именем** («ККТ «Атол
42 ФА»», «ККТ «POScenter-02Ф» Cover», «Фискальный накопитель ФН 15»). Это осознанная
политика: ККТ/ФН регистрируются в ФНС, клиенту нужна юридическая прозрачность.
Обезличиваются только киоски/планшеты/крепления, не фискалка.

## 5. Фискальный пакет по паттерну (без хардкода цен)

Цены фискальных устройств берутся из строк `Тип=фискал` в «Номенклатуре» (не из кода):

| Паттерн | Состав | Когда |
|---|---|---|
| `внешний` | POScenter-02Ф + ФН 15 | Кассы МС Mini/21, SCO D150 — рядом ставится внешний ФР. |
| `внутренний` | Атол 42 ФА (казначей) + ФН 15 (+ встроенный принтер, если задан) | Киоски с местом внутри (SuperKiosk, Sam4s). |
| `встроенный` | Ритейл Комбо-01Ф (в составе киоска, 0 ₽) + ФН 15 | ФР+принтер уже в киоске (K320). Комбо строкой «в составе» для юр. прозрачности, платится только ФН. |
| `нет` | — | Фискализация не требуется. |

Новую модель добавишь в «Правила» с паттерном — фискалка подставится сама. Никаких
списков-префиксов в коде (`KIOSK_FISCAL_RULES` удаляется).

## 7. Планшеты / кронштейны / периферия (лёгкая правка)

Эти листы НЕ ломаем — семейства им не нужны. Две правки:
1. Добавить колонку **`Имя для КП`** (обезличенное) — иначе бренд утекает в КП, а замена
   в превью не работает (сейчас код ищет по обезличенному имени, а в таблице реальное).
2. Калькулятор планшетного Kiosk **читает эти листы**, а не хардкод `catalog.ts` (конец дрейфу).

Плюс чистка данных: убрать дубли имён в «Кронштейнах» («Кронштейн настенный подвижный» ×2,
«Кронштейн настольный» ×2 — добавить G150/G120/G80/G160 в имя), удалить мусорную строку-СУММ
в «Периферии».
